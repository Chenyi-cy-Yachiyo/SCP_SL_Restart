# 回合估算与原生通知设计

用户在确认现有计时把大厅等待和开局倒计时计入后要求继续。采用本地估算方案，默认人数至少 2 人、开局等待 45 秒；人数门槛和等待秒数可以配置。精确回合事件仍需要服务端支持。

## 计时

每台服务器独立维护等待人数、开局倒计时、估算进行中三种状态。等待人数不累加时长；达到门槛的首个有效查询启动倒计时。倒计时人数不足、查询中断、暂停或休眠时取消，重新等待有效人数。进入估算进行中后人数下降到 1 人仍计时，归零或确认掉线时重置。单次查询失败冻结进行中的时长；恢复查询清零连续失败次数。程序中途打开时从观察到的人数重新估算，不补历史。

人数条分别显示「等待2人」「开局0:45」「≈0:00」。保留时长显隐、20 分钟变黄、点击重启提示与通知进服。

## 通知

保留最新版的当前用户通知身份与进服协议注册。使用 PyWinRT 3.2.1 在后台线程内直接创建 XmlDocument、ToastNotification 并调用 ToastNotifier.show；线程显式初始化和释放 WinRT apartment。移除 PowerShell、EncodedCommand、环境变量传参、子进程及执行策略参数。不承诺所有杀软均不误报。

## 验证与交付

回归人数不足、达到门槛、45 秒边界、倒计时取消、暂停/丢包/休眠、运行中降为 1 人、重启复位与非连续失败。通知使用替身验证 XML 转义、进服按钮、系统禁用、异常、线程释放和无子进程。验证实际原生通知与 PyInstaller 单文件依赖，生成新版 EXE，再向最新 main 提交独立 PR。
